# WMMA on RDNA 3

Status: starting document. Tags per [docs/CONVENTIONS.md](../../docs/CONVENTIONS.md). Access dates 2026-10-27.

## Established facts

- [D] RDNA 3 (gfx11) introduced **Wave Matrix Multiply-Accumulate (WMMA)** instructions: `A * B + C ⇒ D`, VOP3P encoding, 16×16×16 tiles; OPSEL bits control 16-bit accumulator read/write halves; no ALU exceptions generated.
  Source: AMD "RDNA3" Instruction Set Architecture reference guide (Feb 2023), https://gpuopen.com/download/rdna3-shader-instruction-set-architecture-feb-2023.pdf
- [D] Supported operand types include INT8/INT4 inputs with INT32 accumulation, and FP16/BF16 inputs with FP32 accumulation. Official HIP builtins expose them, e.g. `__builtin_amdgcn_wmma_i32_16x16x16_iu8_w32` and `__builtin_amdgcn_wmma_f32_16x16x16_f16_w32`; the doc defines per-instruction cycle counts and the theoretical-peak formula `ops/instruction ÷ cycles × frequency`.
  Source: AMD ROCm optimization guide — RDNA3 dense WMMA builtins, https://rocm-handbook.amd.com/projects/amd-rocm-optimization-guide/en/latest/compiler-builtins/rdna/rdna3-dense-wmma-builtins.html
- [D] Operand/register fragment mappings and encodings for RDNA 3/4 WMMA (and sparse SWMMAC) are generated by AMD's official tool (submoded, pinned `2ef9189`): https://github.com/ROCm/amd_matrix_instruction_calculator
- [D] The sanctioned HLSL path to WMMA-class hardware is evolving: SM 6.9 **Cooperative Vector** (retail 2026-02), then **DirectX Linear Algebra** (announced 2026-03, matrix-matrix + vector-matrix). AMD states these give HLSL "direct access to AMD WMMA cores from shaders on AMD Radeon graphics cards".
  Sources: https://devblogs.microsoft.com/directx/shader-model-6-9-retail-and-more , https://devblogs.microsoft.com/directx/cooperative-vector , https://devblogs.microsoft.com/directx/evolving-directx-for-the-ml-era-on-windows/ , https://gpuopen.com/learn/amd-microsoft-gdc-2026
- [S] FSR 4.0.2 reached WMMA hardware from D3D12 HLSL **before** SM 6.9 via AMD's shader-intrinsics extension: `AmdWaveMatrixA/B/Accumulator<AmdExtD3DShaderIntrinsicsWaveMatrixDataFormat_{F16,FP8,F32}, 16, 16>` and `AmdWaveMatrixMultiply(...)` in `pre_wmma.hlsl` / `post_wmma.hlsl` (F16 weights or FP8 operands, F32 accumulators).
  Source: `.references/sources/FSR-4.0.2-reference`, pinned `c5e34b4`, `Kits/FidelityFX/upscalers/fsr4/internal/shaders/post_wmma.hlsl` (L90–194), `pre_wmma.hlsl` (L212–238).

## Relevant implementation details

- INT8 DP4A is the sibling path: HLSL `dot4add_i8packed` (SM 6.4) — used pervasively by FSR 4 INT8 passes (see [inference.md](inference.md)); this is per-lane packed dot, not wave-matrix.
- Distinguish: **theoretical throughput** (ISA cycle counts, rocm-handbook table) vs **measured** throughput — only the latter is engineering truth on gfx1101.

## Unknowns

- [x] ~~Whether driver 32.0.32015.7029 exposes Cooperative Vector (and at what op/format set) on gfx1101~~ — superseded: the AMD intrinsics route was proven end-to-end (EXP-004); CoopVec no longer needed for M06/M07 (would require newer DXC + Agility SDK; recorded as future option).
- [x] ~~What DXC emits (ISA) for INT8 matmul candidates on gfx1101~~ — resolved: `v_wmma_i32_16x16x16_iu8` via the driver shader-analyzer extension (`IAmdExtD3DShaderAnalyzer`), signedness = `neg_lo` modifiers; DP4A control shows `dot4` and no wmma (EXP-004, `build/reports/m06/*.isa`).
- [x] ~~INT8 WMMA latency/throughput in practice on gfx1101~~ — measured (EXP-005): single-tile latency 13.7–20.8 µs; multi-tile 16×16×{64,256} GEMMs are overhead-bound (driver fragment-gather; 2.4–3.1× scaling for 4× K) and DP4A wins 4.2–4.7× at K=64 / 2.2–2.7× at K=256 (prologue amortizes with K); LDS staging is the known optimization direction (FSR4's own pattern). FP16 WMMA ≈ INT8 WMMA in time at these shapes.
