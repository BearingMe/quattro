## 2. Graph (C03)

- [S] 14 model passes per frame (`fsr4_model_v07_i8_pass0` … `pass13`) over one
  byte-addressed scratch buffer; `pre.hlsl` builds the input features and
  `post.hlsl` (KPN) reconstructs the image — both outside this graph and M12
  scope (M13).
- [S] Descriptors are baked constants, not cbuffer data: `logicalSize`,
  `threadGroupSliceStart/Size`, `storageSize`, `storageByteStrides`,
  `paddingBegin/End`, `storageByteOffset`, `quantizationScale`
  (schema: `scripts/m12_extract_graph.py` → `build/reports/m12/graph.json`).
- [S] Weight payloads are split between arrays embedded in the HLSL (67 arrays)
  and `initializers.bin` (11 tensors, 79,360 B used of 89,216 B, byte range
  9,856 … 89,216). Later passes (7–9) and the encoder3 downscale (6) read the
  initializer buffer; everything else uses embedded constants.

- [S] Dispatch grids (non-WMMA path; `ffx_provider_fsr4_dx12.cpp` L1603–1700,

  pass0/post 120×68, pass1/2 15×540, pass3/4/5 8×270, pass6/7/8 4×135,
  pass9 30×17, pass10/11 8×270, pass12 15×540.
- [S] Channel geometry: enc0 960×540 (16 ch), enc1 480×270 (32 ch),
  enc2 240×135 (64 ch); strides are (C, C·W, 1) bytes, i.e. NHWC with
  4-channel dword groups. Storage is a single 20,736,000 B scratch
  ("Scratch memory size needed" in the header).
- [S] Precision boundaries: FP16 input features (7 channels, 8th padded) →
  INT8 at pass 0 → INT8 through pass 12 → FP16 output at pass 13. Per-tensor
  symmetric INT8 scales, including group-specific factors passed to operators.
  Integer convolutions accumulate in INT32; pass 0 instead uses FP16 operand
  pairs with FP32 `dot2add` accumulation. Requantization includes the precise
  bias, residual and scale arithmetic at each boundary, not merely `acc*scale`.
- [S] Passes bake **all** model constants; there are no root constants or
  cbuffers. Consequently the reproduction needs no runtime-constant ABI, and
  M09's cbuffer/analyzer workaround is not implicated.

## 3. Reference execution (C08 reference, evidence)

- [S] `cmake --build --preset debug` compiles the 14 shipped passes unmodified
  from the read-only tree into `build/bin/shaders/m12ref/` and `run fsr4-oracle`
  executes them through `gpu::RunBufferPasses` (root table: t0/t1 SRV, u0/u1 UAV)
  with the provider's grids. Retained runs: `build/reports/m12/ref/run{1,2,3}/`.
- [M] Result on gfx1101 (RX 7700 XT), deterministic synthetic FP16 input:
  16,588,800 output halfwords, **0 NaN, 0 Inf**, 16,588,400 non-zero in
  `ref/run1/run.log`, min −25.65625, max 39.46875. Output:
  `build/reports/m12/ref/run1/output.bin` (33,177,600 B). Nonzero counts vary
  with the race. Earlier one-off smoke numbers are not deterministic targets.
- [M] Passes 0–10 produce bit-identical scratch snapshots across repeated runs.
  **Pass 11 and everything downstream are not deterministic** for the recorded
  synthetic fixture. A labelled predication control is provided to test causal
  attribution; it is not the unmodified reference.

## 4. Negative evidence: reference overhang and a nondeterministic band

- [S] `int8_NHWC/Fused/FNB_CT2D_ADD.hlsli` **32/1 DP4A overload** computes
  `poBase2D = dispatchThreadID.xy * 2 + pk` and stores at L628 **without a
  logical-size predicate**. In contrast, the **64/2 DP4A overload**, used by
  pass 9, explicitly predicates at L263. This literal predicate is not in a
  WMMA overload; the original finding misattributed it.
- [S] Pass 11 writes a 960×540×16 tensor with a 128×2 group tile and a grid of
  8 groups → 1024 output columns for 960 logical columns. The 64-column overhang
  addresses alias into the next row's columns 0–63.
- [M] First retained three-run collection (`determinism.json`): pass-11 scratch
  varies in **58,119 bytes**, x∈[0,63] of 64 rows; final output varies in
  **347,317/16,588,800 halfwords**, x∈[0,131], |Δ| up to **18.8828125**.
  Counts are the union of differences across these three runs, not constants
  per run. The earlier ad-hoc 64,161-byte/936,149-halfword measurements were
  different executions and must not be treated as stable expected counts.
- [M] Causal control: `m12_reference_control.py` copies only the relevant
  operator header under `build/` and inserts the missing 32/1 predicate.
  Three labelled derivative runs (`ref/control{1,2,3}/`) are bit-identical at
  every pass and at final output. Their output SHA-256 is
  `a57bcd063967affddf29cc24709b9d8a7fd9f8e7244e7010521d7b27f605b6de`.
  Unmodified run1 versus control1 differs in **1,131,402 halfwords**, also
  confined to x<132, across 1,076 rows. Thus corruption is more extensive than
  the observed run-to-run variance; stability alone would miss it.
- [M] Natural/tail control in all three original runs: pass9/pass10 have zero
  nonzero bytes beyond logical scratch, whereas pass11 writes **1,021 nonzero
  bytes in the 1,024-byte tail**. All three predicated controls leave it zero.
  These retained measurements support attribution to the unpredicated store.
- [M] A second collection, `verified-determinism.json`, additionally verifies
  identical executable/CSO/control identities and one identical input hash
  across all six runs. Original pass11 varies in 26,915 bytes (33 rows); final
  output varies in 138,585 halfwords, x<132. Its three controls have the same
  stable output hash above. Original/control1 differ in 1,136,197 halfwords
  across all 1080 rows, still confined to x<132. These changed race counts
  reinforce why they are not fixed acceptance thresholds. Input including
  padding: 33,423,360 B, standard FNV-1a `cd3649f34283aec1`.
- [S] The pass-11 trailing store footprint is **1,024 B** beyond the documented
  20,736,000 B scratch (64 columns × 16 B). A historical validation diagnostic
  showing an accessed byte offset 995 beyond the end was not an upper-bound
  measurement; the original “≤995 B” wording was incorrect. The harness now
  allocates exactly this 1,024-byte tail and retains it in captures.
- [S] The separate `float16_NHWC/Fused/CNB_CT2D.hlsli` DP4A store at L283–285
  is also unpredicated. Pass 13 overhangs 1080 rows by 8 rows
  (68×16 = 1088), or **245,760 output bytes**. Pass 0 can read input through
  row 1083. The harness pads physical allocations; this does not establish
  production resource sizing or persistent-frame behavior.
- [H] Scope: this is the **mirror's** generated code compiled for the non-WMMA
  (RDNA 3) path. Whether the signed FSR 4.0.2 runtime on this GPU exhibits the
  same band, and whether the RDNA 4 WMMA path (predicated stores) avoids it, are
  open questions. No claim is made about FSR 4.1.

## 5. Consequences for the reproduction

- [S] The alias footprint is columns 0–63 in the following row. Pass 12's 3×3
  convolution expands that to 0–64; pass 13's 3×3 convolution expands it to
  0–65 before 2× upscaling, giving output columns **0–131**. This is a
  dependency-footprint prediction, not proof of equality for another fixture.
- [H] Comparison should separately quantify the potentially corrupted band
  and the remainder. Run-to-run stability alone does not imply correctness:
  a reference value may be consistently corrupted. Neither a universal
  exclusion mask nor unconditional bit-exactness is established by one fixture.
- [S] The reproduction will use **predicated stores** (write only inside
  `logicalSize`), which is deterministic and is what the WMMA overloads do. The
  resulting difference in the left band is attributable to the reference defect,
  and must be reported as such — not smoothed over.
- [S] A fixed schedule is sufficient; no general graph runtime is required.
  `m12_extract_graph.py` extracts descriptor/array **inventory**, not weight
  payloads. `m12_pack_model.py` now packs all 67 embedded arrays and the complete
  initializer blob without conversion, resolves 78 weight descriptors, and
  retains the numeric prefix arguments from every operator call. Generated
  tables and the 136,848-byte payload stay under `build/reports/m12/`.
